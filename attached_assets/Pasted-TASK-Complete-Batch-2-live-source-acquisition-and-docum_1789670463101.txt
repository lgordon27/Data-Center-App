3. IMPLEMENT A READ-ONLY SEC CONNECTOR

Do not use the account-based EDGAR filing/submission API.

Do not request, store or use Filer API Tokens or User API Tokens.

Use the public read-only SEC interfaces:

- `https://www.sec.gov/files/company_tickers.json`
- `https://data.sec.gov/submissions/CIK##########.json`
- `https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json`
- Official SEC archive filing-document paths

All SEC requests must:

- Run server-side
- Use a declared `User-Agent` from `SEC_USER_AGENT`
- Include a product identity and contact address
- Use conservative throttling of no more than two requests per second
- Cache responses
- Respect `Retry-After`, ETag, Last-Modified and Cache-Control when present
- Avoid repeated retrieval of the same filing
- Preserve CIK, accession number, form, filing date, primary document and retrieval timestamp
- Remain below the SEC’s published fair-access limit

The connector should:

1. Resolve company/ticker to CIK.
2. Retrieve submissions metadata.
3. Filter filings using project/company identity, filing type, date and relevant terms.
4. Construct the official archive-document URL.
5. Pass the document through the bounded document reader.
6. Retain an exact passage only when identity and semantic support are established.
7. Pass the result through the existing evidence-eligibility boundary.

SEC metadata is discovery context, not evidence by itself.

A blocked or irrelevant SEC filing must not consume the entire category or run budget.
