Replace SafeLoc’s prompt-only research plan with a bounded, deterministic, category-based retrieval workflow. Batches 0–2 must already be complete.

CURRENT FAILURE

Two audited Texas project runs each executed only one observed web search, even though the request contained category-specific search plans and allowed up to 32 tool calls. A maximum tool-call budget does not guarantee that the model executes the planned searches.

The application must orchestrate the retrieval categories. Do not rely on one model response to decide whether to search all categories.

RESEARCH CATEGORIES

Run bounded retrieval for:

1. Project identity, campus, phase and parties
2. Grid interconnection and energization
3. Electricity supply, pricing and backup generation
4. Water source, rights, contracts and cooling
5. Permitting, incentives and community agreements
6. Construction status, schedule and capital
7. Tenant/customer/counterparty relationships
8. Climate and operational hazards

For each category:

* Generate a limited primary query.
* Record the exact executed query.
* Retrieve and retain candidates.
* Evaluate coverage.
* Run no more than one focused follow-up query when material coverage remains missing.
* Use one shared time and cost budget.
* Preserve valid results if a later category fails.
* Never report a planned query as executed.

Use appropriate protections for outbound destinations and redirects. Do not build an unrestricted server-side URL fetcher.
