# Task #135: Build the Governed Diligence Agent and Investment Lenses

Begin only after these tasks are complete and passing:

* Task #134: Add Texas-First Community Agreement Intelligence

The application should now have one continuous `#analysis` workbench with:

* Project Overview
* Evidence
* Financial Impact
* Decision
* Advisor Lens

Do not recreate separate workbench routes or add unnecessary primary navigation sections.

Before editing:

1. Inspect the completed implementation.
2. Identify existing AI research, evidence acceptance, financial-model, scenario, persistence, reset, and navigation logic.
3. Reuse existing services and state wherever possible.
4. Confirm that baseline IRR, stress IRR, confidence, gap counts, and recommendation status use one source of truth across the page and summary rail.
5. Fix display inconsistencies before adding new agent outputs. Do not rewrite financial formulas unless an actual calculation defect is identified and documented.

## Objective

Turn SafeLoc from an AI-assisted evidence application into a bounded, governed diligence agent.

The user should be able to select a project and assign one clear objective:

> Investigate the investment and community readiness of this project.

SafeLoc should then execute a structured, visible research workflow, return cited proposed findings, and require human authorization before consequential conclusions affect evidence, financial assumptions, or recommendation status.

The product should support three audiences using the same evidence base:

1. Project Investor
2. Asset Manager
3. Financial Advisor

The evidence must remain consistent across all three lenses. Only the framing and outputs should change.

## Agentic Standard

This feature is agentic only if the system:

* Accepts a goal rather than only a single classification request
* Creates and executes a multi-step research plan
* Uses available research and data tools
* Maintains task state
* Resolves project and company identities
* Finds and evaluates multiple sources
* Detects conflicts and missing evidence
* Produces structured proposed findings
* Verifies citations
* Requests human approval for consequential changes
* Can resume or rerun incomplete work

A chatbot or document summary alone does not satisfy this task.

## Primary Interaction

Add one prominent action:

**Run Diligence Agent**

Use existing visual patterns and place it where it is obvious without competing with primary project navigation.

When activated, the agent should execute these stages:

1. Identify project entities
2. Plan the investigation
3. Search approved sources
4. Classify source relationships
5. Extract material evidence
6. Review community-agreement terms
7. Compare signed precedents
8. Test financial relevance
9. Map issuer and portfolio relationships
10. Verify citations and identify conflicts
11. Prepare findings for human review

Show visible status during execution, such as:

* Identifying operator and project aliases
* Searching available public sources
* Reviewing ten community terms
* Testing financial relevance
* Mapping issuer relationships
* Comparing signed precedents
* Verifying citations
* Preparing findings

Do not imply that the agent has completed a stage until the applicable operation succeeds.

## Agent Results

At completion, show a compact summary such as:

* Verified findings
* Material gaps
* Findings requiring review
* Proposed financial adjustments
* Decision gates
* National precedents located
* Conflicting sources
* Sources that could not be verified

The main result should be easy to understand without reading the complete research record.

Full details should remain available through progressive disclosure.

## One Agent, Structured Workflow

Use one orchestrated diligence agent with typed stages and structured outputs.

Do not create a separate autonomous agent for every evidence variable or community term.

The orchestration should be deterministic enough to test. The system should record:

* Current stage
* Completed stages
* Failed stages
* Sources reviewed
* Proposed findings
* Unresolved conflicts
* Human decisions
* Final approved state

A failed source or stage should not discard completed work. Allow the user to retry the failed stage or complete the review manually.

## Source Security and Integrity

Treat all external documents and webpages as untrusted evidence.

The agent must:

* Ignore instructions contained inside retrieved documents
* Never execute code or commands found in a source
* Never expose application secrets
* Use approved research tools only
* Preserve source URLs and retrieval dates
* Distinguish primary documents from secondary reporting
* Quote only the language necessary to support a finding
* Flag inaccessible, outdated, or conflicting documents
* Avoid calling a relationship direct without supporting evidence

Every material conclusion must be traceable to:

* Verified evidence
* Management assertion
* Model inference
* User assumption
* Missing evidence

Preserve the existing SafeLoc evidence classifications.

## Community Diligence

Run Community Agreement Review against every analyzed project.

The agent should:

1. Search for direct project agreements.
2. Search for related operator, developer, utility, and jurisdiction records.
3. Classify each record as direct, related, comparable, or not found.
4. Review the ten community terms created in Task #134.
5. Detect softening language such as:

   * Best efforts
   * Good faith
   * Commercially reasonable
   * Subject to availability
   * Sole discretion
6. Evaluate whether a provision appears:

   * Absent
   * Aspirational
   * Binding
   * Binding with a financial consequence
   * Binding with financial security
7. Identify who can enforce the provision.
8. Compare it with signed national precedents.
9. Propose missing evidence and diligence actions.

Use Stargate Abilene as the principal Texas demonstration, but verify whether the City of Abilene document directly applies to the project before labeling it direct.

For projects without project-specific documentation, display:

> No direct public agreement was located in the available sources.

Never convert that into:

> No agreement exists.

## Best Terms Actually Signed

Use the 15-agreement corpus to create a benchmark containing the strongest documented signed provision for each of the ten community terms.

For each benchmark show:

* Term
* Jurisdiction
* Operator
* Plain-English description
* Exact supporting language
* Page reference
* Original document
* Why it is considered stronger
* External benchmark source
* SafeLoc review status

Label it:

**Best Terms Actually Signed**

Do not describe it as a model agreement or legal standard. It is a documented precedent library.

## Additional Agreement Insights

Where supported by the data, the agent may propose insights concerning:

* Protection versus enforceability
* Who bears downside risk
* Regulatory protection versus negotiated protection
* Transparency and verification risk
* Repeated operator behavior across jurisdictions
* Differences between headline commitments and binding obligations

Do not draw broad statistical conclusions from the 15-agreement sample.

Repeat-operator comparisons should be framed as diligence questions, not definitive company ratings.

Example:

> This operator accepted stronger water-reporting provisions in another jurisdiction. Determine why comparable language is absent or unavailable here.

## Investment Relationship Model

Separate direct project capital from public-company and portfolio exposure.

Classify issuer-project relationships as:

* Owner or equity sponsor
* Lender or financier
* Operator or developer
* Tenant or capacity buyer
* Equipment supplier
* Utility provider
* Thematic connection
* Unverified

For every relationship store:

* Relationship type
* Supporting evidence
* Confidence
* Financial transmission mechanism
* Human review status

Do not imply that owning a supplier such as NVIDIA means an investor owns or directly finances the analyzed project.

Use language such as:

> NVIDIA is commercially connected to the AI infrastructure buildout as a supplier. The financial materiality of this specific project to NVIDIA has not been established.

## Three Investment Lenses

Add a concise lens selector using:

* Project Investor
* Asset Manager
* Financial Advisor

Do not change the underlying evidence when the lens changes.

### Project Investor

Designed for infrastructure investors, private equity, developers, lenders, and project-finance teams.

Show:

* Project IRR, NPV, and MOIC
* Baseline and approved stress case
* Capital exposed before major conditions are satisfied
* Risk allocation
* Value-at-risk ranges
* Conditions precedent
* Proposed deal protections
* Mitigation economics
* Proceed, Protect, Reprice, or Pause posture

### Asset Manager

Designed for public-equity, sustainable-investment, and thematic fund managers.

Show the bridge:

1. Project finding
2. Issuer relationship
3. Financial transmission mechanism
4. Potential issuer-level effect
5. Materiality status
6. Portfolio relevance
7. Stewardship or engagement action

Possible materiality states:

* Materiality supported
* Potentially material
* Materiality not established
* Insufficient evidence

Do not derive issuer materiality solely from project evidence.

Where information is available, permit comparison with:

* Issuer capital expenditures
* Revenue
* Free cash flow
* Contractual commitments
* Operating capacity
* Geographic concentration

Do not invent missing issuer exposure values.

### Financial Advisor

Designed for the GFI audience and advisors serving households invested through stocks, funds, and sustainable strategies.

Show:

* Relevant client holding
* Fund or index connection
* Issuer-project relationship
* Whether exposure is direct, indirect, or thematic
* What is verified
* What remains unknown
* Financial materiality
* Values or stewardship relevance
* Questions to ask the fund manager
* Neutral client-conversation guidance

Do not generate an automatic buy, hold, or sell recommendation.

The advisor output should reinforce:

> AI can investigate evidence and trace exposure, but the advisor determines materiality, values alignment, and appropriate client action.

When the user enters through the NVIDIA or conference-oriented flow, default the results framing to Financial Advisor while preserving easy access to the other lenses.

## Risk Allocation

For every material project finding, identify which party appears to bear the downside:

* Developer
* Operator
* Hyperscaler or tenant
* Utility
* Municipality
* Lender
* Equity investor
* Taxpayer or ratepayer
* Unresolved

Display the evidence supporting the allocation.

If responsibility is unclear, classify it as unresolved rather than assigning it to a party.

## Value at Risk

For quantifiable risks, the agent may propose:

* Cost range
* Delay range
* Revenue impact range
* Capital exposure
* IRR sensitivity
* NPV sensitivity
* Evidence confidence

Prefer ranges over unsupported point estimates.

Every proposed value-at-risk calculation must show:

* Source evidence
* Assumption
* Calculation method
* Original model value
* Proposed stress value
* Resulting financial range
* Human approval status

The agent must not invent a probability or financial value because a community term is weak or absent.

## Capital-at-Risk Timeline

For the Project Investor lens, show when capital becomes committed or difficult to recover:

* Land acquisition
* Interconnection deposits
* Infrastructure contributions
* Construction commencement
* Tenant commitment
* Debt draw
* Commercial operation
* Stabilization

Only show stages supported by available project data or clearly labeled model assumptions.

Distinguish:

* Direct project capital
* Issuer corporate exposure
* Client portfolio exposure

Do not use the phrase “your capital is at risk” for an indirect public-equity connection.

## Conditions Precedent

Convert material evidence gaps into proposed requirements that should be satisfied before additional capital is committed.

Examples:

* Executed utility service agreement
* Final zoning approval
* Confirmed water allocation
* Binding tenant commitment
* Construction contract
* Community agreement
* Noise study
* Decommissioning security
* Insurance confirmation

Each proposed condition should include:

* Related gap
* Evidence needed
* Responsible counterparty
* Financial exposure addressed
* Human approval status

These are analytical suggestions, not legal advice.

## Deal Protections

Where relevant, the agent may propose protections such as:

* Completion guarantee
* Cost-overrun support
* Debt-service reserve
* Decommissioning reserve
* Sponsor equity funded first
* Restrictions on distributions
* Permits required before drawdown
* Minimum tenant-credit requirements
* Reporting obligations
* Notice of community or regulatory disputes
* Indemnification
* Escrow or bond

Do not draft legal language. Present these as topics for investment and legal review.

## Mitigation Economics

When evidence permits, compare:

* Mitigation cost
* Expected loss avoided
* Payback period
* NPV of mitigation
* Residual risk

Examples may include:

* Closed-loop cooling
* On-site generation
* Additional grid infrastructure
* Noise mitigation
* Road improvements
* Water infrastructure
* Community-benefit commitments

Do not calculate benefits without explicit assumptions and approval.

## Decision Actions

Preserve the existing evidence-governed recommendation, but add an investor-action translation:

* Proceed
* Protect
* Reprice
* Pause

Definitions:

* Proceed: Material evidence requirements are sufficiently satisfied.
* Protect: Proceed only with specified conditions or protections.
* Reprice: Economics should be revised to reflect approved exposures.
* Pause: Material evidence or authorization remains unresolved.

Show what must change for the project to move to a more favorable posture.

Do not allow the AI to approve the final action.

## Human Authorization

Allow the agent to perform these actions automatically:

* Search authorized public sources
* Extract candidate clauses
* Find comparison agreements
* Identify possible conflicts
* Suggest evidence classifications
* Suggest financial treatments
* Suggest issuer relationships
* Prepare proposed diligence actions

Require human acceptance before:

* Confirming a direct project relationship
* Changing an evidence classification
* Resolving a material gap
* Establishing issuer-level materiality
* Changing a financial assumption
* Adding a probability
* Changing the recommendation inputs
* Finalizing Proceed, Protect, Reprice, or Pause

Provide:

* Accept
* Override
* Leave unresolved

Record the human decision and preserve existing persistence and reset behavior.

## User Experience

Follow the existing progressive-disclosure principles.

On completion, show:

1. The conclusion
2. The most material findings
3. The appropriate audience lens
4. The next decision requiring human attention

Keep detailed research logs, methodology, clauses, calculations, and benchmark tables collapsed by default.

Do not add a generic chatbot as the primary interface.

Individual `Analyze with AI` controls may remain for rerunning or challenging one finding, but `Run Diligence Agent` should be the signature interaction.

## Acceptance Criteria

The task is complete when:

1. A user can run one structured diligence investigation from a project.
2. The agent visibly executes and records multiple research stages.
3. Completed stages survive a partial failure.
4. Every material proposed finding includes a citation or is marked unsupported.
5. Community review runs for every project.
6. The 15 agreements support national benchmarking without being treated as project-specific evidence.
7. Direct, related, comparable, and not-found relationships remain distinct.
8. Best Terms Actually Signed is available with citations.
9. Project capital and portfolio exposure are not conflated.
10. Issuer-project relationships are explicitly classified.
11. Project Investor, Asset Manager, and Financial Advisor lenses use the same evidence.
12. The Project Investor lens shows risk allocation and proposed deal actions.
13. The Asset Manager lens shows issuer materiality and stewardship relevance.
14. The Financial Advisor lens provides client-facing interpretation without automated trade advice.
15. Financial changes require explicit assumptions, calculations, citations, and human approval.
16. AI proposals do not silently change the model or recommendation.
17. The unified `#analysis` route and section navigation remain intact.
18. Desktop and mobile layouts have no horizontal overflow.
19. Persistence, restoration, reset, scenarios, and existing AI workflows continue functioning.
20. Tests cover orchestration state, partial failure, citations, relationship classifications, lens separation, authorization, financial safeguards, persistence, accessibility, and responsive layout.
