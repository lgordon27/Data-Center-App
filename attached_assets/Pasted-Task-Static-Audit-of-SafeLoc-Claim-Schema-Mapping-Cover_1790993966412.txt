Task: Static Audit of SafeLoc Claim Schema, Mapping Coverage, and “claim-not-mapped” Failures

This task runs in parallel with the evidence-conversion instrumentation task.

READ-ONLY DIAGNOSIS ONLY.
Do not change code.
Do not run live/provider requests.
Do not modify prompts, schemas, eligibility, identity, scope, ranking, budgets, or UI.

The purpose is to determine whether SafeLoc’s current structured-analysis schema and downstream mapping layer are capable of representing the kinds of valid project facts the research engine is actually finding.

Recent live validation showed:
- 69 traced records across eight runs;
- 51 primary `claim-not-mapped`;
- 7 `missing-passage`;
- zero eligible findings.

We need to know whether `claim-not-mapped` is primarily:
A. expected placeholder behavior,
B. missing source support,
C. a schema/mapping coverage problem,
D. field normalization mismatch,
E. unsupported project facts that SafeLoc currently has no destination for.
