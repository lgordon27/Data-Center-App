Task: Instrument SafeLoc’s Evidence-Conversion Pipeline and Identify the Exact Causal Bottleneck

This is now the highest-priority SafeLoc task.

Do not implement a broad repair yet.

The latest multi-project validation established:
- source discovery is not the primary problem;
- relevant passages are being retained;
- IREN and Vantage retained relevant project text but sent zero distinct assessment text hashes to OpenAI;
- AWS sent some text to OpenAI but still produced zero eligible findings;
- current diagnostics are too coarse to prove whether the dominant failure is pre-OpenAI admission, OpenAI structured analysis, post-OpenAI mutation/source mapping, identity/scope validation, or multiple comparable bottlenecks.

The purpose of this task is to make the full evidence-conversion path observable enough that we can identify the first causal loss for each substantive claim and then repair the correct stage.

This is not a UI task.
This is not a discovery-ranking task.
This is not backtesting.
This is not database housekeeping.
This is not a provider/model rewrite.

==================================================
PRIMARY OBJECTIVE
==================================================

Instrument the production-path funnel:

retained passage
→ category routing/admission
→ identity admission
→ deduplication
→ category passage window
→ token fitting
→ OpenAI input
→ raw OpenAI structured output
→ source restriction
→ normalization/parsing
→ identity evaluation
→ scope evaluation
→ source/quotation mapping
→ eligibility
→ claim containment

For every substantive candidate, identify:
1. whether it reached each stage;
2. if not, the exact first causal failure;
3. which later stages were not evaluated;
4. whether the failure is a legitimate evidence/scope rejection or an internal engine defect.
