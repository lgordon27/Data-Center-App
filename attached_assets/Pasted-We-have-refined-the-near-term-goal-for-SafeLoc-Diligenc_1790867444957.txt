Definition of proof-of-system

A user should be able to enter a real data-center project that was not specifically hard-coded into the app.

SafeLoc should then:

1. Establish correct project identity.
2. Search for relevant current evidence.
3. Retrieve and clean actual source documents/passages.
4. Preserve attribution, dates, source URLs, project/phase scope, and research receipts.
5. Classify what is:
    * Confirmed
    * Expected, not located
    * Located but insufficient
    * Contradictory
    * Not expected yet
6. Determine maturity/status for the relevant diligence categories.
7. Determine whether each finding has a defensible financial transmission mechanism.
8. Classify financial interpretation as:
    * Direct
    * Derivable
    * Scenario-only
    * Unresolved
9. Classify transmission confidence as:
    * T0: no transmission established
    * T1: plausible pathway
    * T2: project-specific pathway established
    * T3: quantifiable
10. Propose financial/model changes only where evidence permits.
11. Require human acceptance before any research changes the financial model.
12. Recalculate the financial analysis after accepted changes.
13. Produce a coherent final project analysis.
14. Preserve evidence/state history rather than simply overwriting prior states.

Unknown must remain unknown. Failed retrieval must never become evidence that something does not exist.

Expected Evidence

The system should not merely ask, “What did I find?”

It should ask:

“Given this project’s stage, scale, type, location and known design, what evidence should I reasonably have looked for?”

Expected Evidence must never mean a document definitely exists.

The output states should be:

* Confirmed
* Expected, not located
* Located but insufficient
* Contradictory
* Not expected yet

If important expected evidence is absent, the system should be capable of a targeted second-pass search for that category.

Example for power:

project + utility
project + interconnection
project + substation
project + transmission
project + load
project + PUC
project + tariff

Equivalent targeted search logic can exist for other categories.

Financial transmission model

The core rule is:

SafeLoc may identify a transmission mechanism from evidence, but may only quantify financial impact when the magnitude is:

1. directly evidenced;
2. mechanically derivable from evidenced facts; or
3. explicitly entered/selected as an illustrative scenario.

No unrestricted LLM-to-financial-model write path.

Pipeline:

eligible evidence
→ approved mapping rule
→ transmission mechanism
→ financial variable
→ quantification state
→ human acceptance
→ financial model

Examples:

* energization date moved 6 months
    → COD/revenue timing shift
* delivered MW reduced
    → capacity change
* documented utility infrastructure cost
    → capex
* water infrastructure cost
    → capex
* construction delay
    → COD / spend timing
* debt rate change
    → financing cost
* tenant commencement delay
    → revenue/utilization timing
* incentive revoked
    → tax/cash-flow impact

Community opposition alone should NOT produce a financial value.

Example:

organized opposition
→ no direct model change

But:

opposition causes official 90-day hearing delay
→ project-specific schedule pathway
→ possible COD transmission

Similarly:

water-stressed location
→ no automatic MW/capex assumption

But:

municipality requires a documented $45M water connection
→ +$45M capex candidate

Current Phase 1 bottlenecks from Red Oak

A recent Red Oak run showed:

1. OpenAI category analysis hit a 30,000 TPM rate limit.
2. Category prompts were about 11k input tokens each across eight categories.
3. Gemini discovery used roughly 34 seconds of the 75-second run.
4. Multiple categories were cancelled before completion.
5. Every DataBank first-party page was blocked by the current SSRF/DNS safety system as private/special-purpose.
6. Do not loosen SSRF protections without understanding the DNS behavior.
7. A strong TDLR source was retrieved:
    * DataBank Red Oak – DFW10
    * $301M estimated cost
    * 221,434 sq ft
    * start 2/1/2025
    * completion 1/31/2027
    * owner DB Data Center Red Oak, LLC
8. That TDLR evidence never became eligible because its category analysis failed.
9. Its retained passage contained raw HTML.
10. Error/boilerplate pages were treated as valid content.
11. Telemetry repeats the same documents excessively.

Phase 1 remains the bottleneck. If the system finds authoritative information but cannot preserve it into eligible evidence, none of the new layers matter.
