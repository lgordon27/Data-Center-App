Build modelEvidence as INITIAL_EVIDENCE overlaid with the dossier's records, joined on variableId. The dossier record's classification, value, and source replace the synthetic one for that variable.

1.3 Let human decisions move the model

Problem:

updateClassification returns early for any canonical dossier: if (project.canonicalDossier) return false (~line 620). All classification selects on Abilene are disabled with no explanation.
For custom projects, financialModeling (~lines 534–538) returns "modeled" only for slug === "stargate-abilene", so human-accepted research can never reach a visible model.

Fix:

Remove the early return. On canonical dossiers, classification changes become session overrides: stored separately from the maintainer baseline, marked "Session override" on the row, recorded in the decision trail, and cleared by Reset. The maintainer-reviewed dossier in PostgreSQL is never modified.
Accepting an AI proposal on a dossier applies it the same way, as a session override.
Replace the slug check in financialModeling with a rule:
Canonical dossier with an approved financial scenario → modeled.
Custom project → "Illustrative model" becomes available only after (a) a human has accepted at least one proposal-eligible input and (b) a human has entered an illustrative capacity (see 2.2). Label every output "Illustrative — not project economics".
Otherwise → not modeled, with the existing required-inputs list.
Add a one-line explanation wherever a control is disabled, stating why.

Acceptance:

Abilene: change Facility Water Rights from Missing Evidence to Verified Evidence. The classification counts, IRR, and recommendation status update immediately; the row shows "Session override"; the decision trail records it.
Accept an AI proposal on Abilene: the same effects occur.
Reset restores the pass 1.2 baseline exactly.
Reload the page: session overrides persist until Reset.
1.4 One definition of "unresolved" and "known"

Problem:

generateAdvisorBrief recomputes unresolved (src/model/conferencePresentation.ts ~57–61) without excluding items already listed as facts. Abilene's Oracle relationship and Kilby's Microsoft PPA appear under both "What We Know" and "What We Do Not Know".
For canonical dossiers, getConferenceEvidenceSummary (src/model/conferenceEvidence.ts ~307–319) treats any non-Missing sourced item as a fact, including Management Assertions.
Gate counts disagree: Financial Transmission uses metrics.unresolvedDecisionGateCount (1 on Abilene); Advisor Brief uses unresolved.length for dossiers (2).

Fix:

Create one shared helper that classifies each evidence item into exactly one bucket:
Established: Verified Evidence with a source.
Reported, not verified: Management Assertion or attributed reporting with a source. Show what was reported and by whom.
Open: Missing, partial, conflicting, or ambiguous applicability.
Use it in Project Reality, Financial Transmission, Advisor Brief, and the Asset Manager brief. No item may appear in two buckets.
Decision gates and financial drivers are counted from the same helper, filtered by impact role, everywhere. Show both counts on both tabs.

Acceptance:

On Abilene, Kilby, and El Mirage, no item appears in more than one bucket.
Gate and driver counts are identical across all tabs for each dossier.
A test fails if any item appears in two buckets or if the counts differ between tabs.
